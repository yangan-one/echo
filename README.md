# 回响 Echo · V1

> 不教新词，只修你已有的漏洞。
>
> 一款"你指出卡点、AI 负责修改"的英语听说训练器。

面向已经能听懂、敢开口，但**听的时候总要绕一道中文、说的时候先想中文再逐字翻译**的学习者（B2–C1 区间）。它不提供课程、题库和背单词，只做一件事：把你口语里卡住的那几秒找出来，给出你真能说出口的替换说法，然后让你只重录那几秒。

## 〇·〇·〇·〇·〇、V3.0：账号 + 服务器代调模型

这一版从「纯前端单机」变成「前端 + 一个很小的 Node 服务」，因为两件事前端做不到：

1. **账号与跨设备数据**：注册 / 登录后，训练记录和录音存在服务器，换电脑、换手机登录同一个邮箱就能看到自己的数据。
2. **用户不用再填 API Key**：建议请求发到本站服务器，由服务器用**运营者自己的一个 key** 统一调用模型。用户侧没有任何配置项。

### 用户看到的变化

- 打开就是一个登录 / 注册页（邮箱 + 密码，密码至少 6 位）。
- 登录后，首页、卡点库、进度都跟着账号走。
- 设置页只剩：显示名、数据导出 / 导入、清空、退出登录，以及一行「AI 建议由服务器提供」的状态。
- 原来那堆「必须填 key 才能用远程」的输入框删掉了；需要自带 key 的人，去设置页最下面的「用我自己的 key（可选）」填。
- 设置页多了一张「用我自己的 key（可选）」卡片：留空就用站点额度；填了自己的 DeepSeek key，建议请求由浏览器直连服务商，**不消耗站点 token**。这把 key 只存在本机 localStorage，不会随账号同步（同步前会 strip 掉 `ai` 字段），换设备需重填。


### 架构

```
浏览器（React，IndexedDB 缓存）
   │  /api/*
   ▼
Node 22 + Express（本仓库 server/）
   ├─ 账号：scrypt 密码哈希 + HMAC 签名 token（30 天）
   ├─ 状态：data/db.json（整份 state 按用户存）
   ├─ 音频：data/audio/<userId>/<audioId>.bin
   └─ 代理：/api/ai/chat/completions、/api/asr/v1/audio/transcriptions
              │ 用服务器环境变量里的 key
              ▼
           DeepSeek / OpenAI 等兼容接口
```

前端仍然先在本地存一份（IndexedDB + localStorage），再**防抖 1.2 秒**同步到服务器；断网时照常能用，恢复后自动补同步。

### 运营者要配的东西（只配一次，用户不用管）

| 环境变量 | 作用 | 不配会怎样 |
|---|---|---|
| `ECHO_AI_KEY` | 服务器调用模型的 key（DeepSeek / OpenAI 都行） | 建议自动退回内置离线库 |
| `ECHO_AI_BASE_URL` | 默认 `https://api.deepseek.com/v1` | — |
| `ECHO_AI_MODEL` | 默认 `deepseek-chat` | — |
| `ECHO_ASR_KEY` | 可选，Whisper 类转写 key（**不会**默认复用 AI key） | 退回浏览器识别 |
| `ECHO_SECRET` | 签发登录 token 的密钥，**上线必须改** | 用默认值 = 谁都能伪造登录 |
| `ECHO_DATA_DIR` | 数据目录，默认 `./data` | — |

本地开发把上面几项写进项目根目录的 `.env` 即可（`server/env.mjs` 会读它，`.env` 已在 .gitignore/.dockerignore 里）。

成本口径：一次建议约 1–3k token，DeepSeek 上是「几厘钱」的量级；五十个朋友每天各练两次，一个月大概是杯咖啡钱。

### 部署

**方式 A：Docker（任意 VPS / Render / Railway / Fly）**

```bash
docker build -t echo .
docker run -d -p 8788:8788 \
  -e ECHO_SECRET=$(openssl rand -hex 32) \
  -e ECHO_AI_KEY=sk-你的key \
  -v echo-data:/app/data \
  echo
```

容器里一个进程同时提供页面、`/api/*` 和音频，`/app/data` 必须挂持久卷，否则重建即清空。

**方式 B：Render（仓库里有 `render.yaml`）**

1. 把项目推到 GitHub，Render 里 New → Blueprint，选这个仓库；
2. 它会按 `render.yaml` 建服务，把 `ECHO_AI_KEY` 填成你的 DeepSeek key；
3. 加一块 1GB 磁盘挂到 `/app/data`（免费实例不含磁盘，需要 Starter 起）；
4. 部署完成后拿到 `https://<name>.onrender.com`，发给谁都能用。

**方式 C：本机先跑起来**

```bash
npm run server     # 8788，同时服务 dist 和 API
npm run dev        # 5180，开发时用，/api 自动代理到 8788
```

### 这一版的安全边界（请知悉）

- 密码用 scrypt 加盐哈希，token 是 HMAC 签名，30 天过期；**没有**邮箱验证、找回密码、限流验证码。
- 数据存在单机 JSON 文件里，适合几十到几百人的小范围使用；再大要换 Postgres + 对象存储。
- 音频按用户隔离，取音频要带 token；但链接拿到后 24 小时内可重放（私有缓存）。
- 公开上线前至少做：改 `ECHO_SECRET`、给 `data/` 做定期备份、在反向代理层加请求体大小限制。

## 〇·〇·〇·四、V2.4：换掉"泛黄纸感"

原来的底色是暖米黄（`#f5f0e6`）+ 米白卡片，读久了发闷，也不像现代应用。这一版整体换成中性冷灰白：

- **底色**：`#f3f4f6`，顶部一层很淡的白光，右下角一点冷灰，不再有黄调。
- **卡片**：纯白 `#ffffff`，1px 冷灰描边 + 极轻阴影，圆角 14px。
- **文字**：近黑 `#12161c`，二级 `#333942`，辅助 `#5c6573`；正文仍是系统无衬线，标题保留衬线（这是唯一保留的"旧"元素，换成无衬线会失去辨识度）。
- **强调色**：从赭红改成 **松绿 `#1f6b57`**——品牌点、kicker、主按钮都用它；六个标签的色值不动（它们是数据，不是装饰）。
- **主按钮**：实心墨绿，hover 加深；录完那一屏的收尾按钮降级为描边，不再两个大色块对撞。
- **其余**：波形底、原文引用块、选项行、输入框全部去黄；焦点态加了绿色 outline（键盘可用）；表格/列表分割线统一到 `#e6e8ed`。

对比：旧版 `#f5f0e6` 暖纸 → 新版 `#f3f4f6` 冷灰 + 纯白卡片 + 松绿强调。

## 〇·〇·〇·二、V2.2：建议落在"你自己那句话"上

之前离线建议的最后一层是「按标签给模板」——不管你说的是什么，选「不地道」就给你 `The point is…`。这一轮补上了一层：**没有材料原句可对、也没有中文概念命中时，直接改你自己说的那句。**

- 新增「自己的句子升级」通道（`src/lib/ai.ts` 的第 4 步）：当你标了「不地道」或「太啰嗦」，且你输入的原句是一个完整从句（≥5 词、含谓语）时，给出三条——
  1. 缩略 + 去垫话：`I think that this is not very good` → `I'd say this isn't very good for the team.`
  2. 加引子：`What I mean is, this isn't very good for the team.`
  3. 换开头：`Put it this way: this isn't very good for the team.`
- 缩略表 28 条：`do not→don't`、`is not→isn't`、`I am→I'm`、`I think→I'd say`，并去掉 `kind of / sort of / you know` 这类填充。
- 建议卡右上角的来源标签改成「离线生成 / 离线规则 / 远程模型」，不再一律写"离线短语库"。

工程与可访问性：`ai.ts` 从 858 行拆到 778 行，数据与 prompt 分到 `src/data/patterns.ts`、`src/data/judgements.ts`、`src/lib/prompts.ts`；`scripts/selftest.mts` 增加了材料定位、判断句、硬伤、完整句、句子升级五组断言（`npm test`）；系统没有可用语音包时，建议卡的 ▶ 变成 ⧉，点一下复制这句话。

## 〇·〇·〇·一、V2.1：30 秒短版（素材不再是"从半句切进去"）

原先 43 段素材都是 75 秒，而且是从别人说话的中途切进去的：第一句是半句，最后一句也是半句。现在每段素材多了一条 **30 秒短版**：

- **从一句话的开头切入**：用 TED 官方英文字幕里上一句的句末标点 + 下一句首字母大写来判定句子边界，切点落在句首。
- **在最后一个完整句的句尾收住**：不留半句。音频时长因此每条略有不同（29–32 秒）。
- **文本与音频一一对应**：短版有自己的英文文本（滚动字幕的重复句已折叠）和中文翻译；切到「完整 75 秒」时用回原来的全文。
- **默认进短版**：听一遍 30 秒、讲 60 秒，比每次啃 75 秒更容易坚持；想练长材料点「完整」。
- 生成链路：`scripts/short_build.mjs`（4 路并发拉字幕 + ffmpeg 切片）→ `scripts/short_result.json` → `scripts/gen_short.mjs` → `src/data/shorts.ts`（`SHORTS` + `shortOf(audioUrl)`）。

> 有 14 条短版没有中文：这些 TED 新演讲本来就没有官方中文字幕，短版的句子和全文对不上，就不硬凑了——这些条目在短版下不显示「对照中文」，切到「完整」还能看全文译文。
>
> 顺手修了一个旧 bug：最早的 6 条（Ken Robinson / Brené Brown / Simon Sinek / Celeste Headlee / Chimamanda / Susan Cain）当时把 TED talk id 填错了，音频其实是别人的演讲。这一轮用 talk 页解析出的正确 id 重切了 75 秒音频，文本与译文也按新窗口重取了。

## 〇·〇·四、V1.8：字幕重复句清理 + 即兴题 54 道

- **清理字幕重复**：TED 的滚动字幕会把同一句重复两遍（`time for part two: a math test. time for part two: a math test.`），之前只折叠了整句完全相同的，跨标点、半句重复的漏掉了。现在 `scripts/fix_text_dupes.mjs` 做三层处理：① 相邻整句去重；② 后一句是前一句后缀时删掉；③ 词级扫描，跨标点找出连续重复 ≥5 个词的片段并删除。43 条素材全部过了一遍，重复句清零；中文对照的相邻重复句也一并清掉。剩下唯一一处 8 词重复是 Jinsop Lee 里同一短语在不同段落各用一次，属于正常表达，保留。

## 〇·二、V1.3 改了什么（2026-11-03 第三轮）

- **朗读不再"点了没反应"**。Chrome 的 `speechSynthesis` 有个老问题：`cancel()` 紧接着 `speak()`，新的朗读会被安静丢弃。现在先 cancel → resume 解开暂停态 → 等 90ms 再 speak；播放图标由 `onstart` 驱动，不再只是"设了状态"。切 0.8×/1.2× 会立刻按新语速重播，不用再点一次播放。若 1.6 秒内合成器仍未启动，会在播放条下方直接说明原因（多半是没装语音包），而不是假装在播。
- **录音开头不再吞音**。原来 MediaRecorder 和语音识别几乎同时启动，识别会抢占麦克风，前 1–2 秒容易空。现在先把音频上下文跑起来、等 220ms 预热再开录音，语音识别延后 600ms 启动；停止时先 `requestData()` 把缓冲刷出来。
- **综述前先给一版主旨**。录完 60 秒进入回听页，最上方先出现「材料主旨 · 参考」：3 句口语版综述（先主旨 → 一两个细节 → 收尾），看完再往下听自己、打标。20 条内置素材各配了一版手写综述（`src/data/gists.ts`）；远程模式下会用模型按材料原文重新生成，你上传的材料也能用。
- 开发脚本加了 `usePolling`：Windows 下原生 watcher 偶尔漏事件，会出现"改了代码页面还是旧的"。

### V1.3 第二轮（同日，针对实测反馈）

- **开麦预热 1.2 秒再录**：点「开始录音」后先开流、跑音频图、界面显示「麦克风准备中，等计时开始再说话」，预热结束才开始 `MediaRecorder`。前 1 秒的毛刺落在录音之外。
- **判断句通道**：当中文意图是一个判断（不准确 / 站不住 / 片面 / 夸大 / 过时 / 双标），不再套"想不起词"的绕词模板，直接给 3–5 条完整判断句，例如 `That claim isn't accurate.` / `That's only part of the picture.`。
- **换一条建议真的会变**：判断句有 5 条，按次轮换 3 条；换完有提示。离线短语库本身说法有限，远程模式才会真正重写。
- **重新生成有反馈**：离线参考是固定三条，重算后明确告诉你"离线不会变，远程才会变"，不再像按钮失灵。
- **转写失败说清原因**：浏览器自带识别走在线服务，国内网络常连不上；现在 `network` 错误会明确提示，并且没有转写时提供「手动补一句」直接打标。

## 一、现在能跑通的两条链路

**链路 A：听力闭环**

```
选素材 → 听（可调速 / 看原文）→ 限时 60 秒英文综述录音
      → 回听自己的录音，在波形上打标 → AI 给 2–3 个平行说法
      → 只重录那几秒（说够了再点停止，不设上限）→ 新旧对比 → 进入卡点库
```

**链路 B：即兴闭环**

```
随机主题 → 限时 60 秒开口 → 回听打标 → 一条核心建议
        → 同题再说一遍（version 2）→ 两版并排比较 WPM / 停顿 / 填充词
```

两条链路共用**卡点库**（待重录 / 已重录 / 暂不修）与**进度页**，形成"发现漏洞 → 修补 → 复现"的飞轮。

### 六个卡点标签（产品的最小数据模型）

| 标签 | 什么时候按 |
| --- | --- |
| 词穷 | 想不起那个词 |
| 说错 | 说出了错句 |
| 太啰嗦 | 意思对，但绕了半天 |
| 不地道 | 没错，但不像母语者会这么说 |
| 语气不对 | 想更狠 / 更软 / 更委婉 |
| 接不上 | 逻辑断了，不知道下一句说什么 |

打标时用中文写一句"我当时想说什么"，是建议质量的关键输入。

## 四、AI 建议：两种模式

设置页 →「建议从哪来」：

| 模式 | 说明 | 适合 |
| --- | --- | --- |
| 离线短语库 | 内置约 25 组中文概念（各取所长、权衡利弊、说到底…）+ 十余条常见硬伤规则 + **先定位材料原句**再改写 | 不联网、零成本；只覆盖常见模式 |
| 远程模型 | 任意 OpenAI 兼容接口（`/chat/completions`、JSON 输出） | 真正读懂你说了什么，覆盖最广 |

**建议是怎么来的**（两种模式都遵守）：

1. 先看你标的那句话 + 你写的中文意图；
2. 在材料原文里找**对应的那一句**（逐字显示在建议卡里，标为「材料原句」）；
3. 围绕这一句，给 2–3 条**完整的、能直接说出口的句子**（不是一个词，也不是 `which brings me to…` 这种半句）；
4. 只在材料里确实找不到对应句时，才回到"按标签给通用建议"，并在正文里说明这一点。

远程模式要填三样东西（设置页里有解释和「快速填」按钮）：

- **Base URL**：接口地址的前半段，程序会自动补 `/chat/completions`。OpenAI 是 `https://api.openai.com/v1`；DeepSeek 是 `https://api.deepseek.com/v1`。中转/代理服务填它给你的那个前缀。
- **API Key**：在服务商控制台里创建的那串密钥，通常以 `sk-` 开头。它只存在你这台机器的浏览器里，请求由浏览器直接发出，V1 没有转发服务端。
- **模型**：服务商文档里的模型名，例如 `gpt-4o-mini`、`deepseek-chat`。填错不会报错，只是调用失败后自动退回离线库。

其他要点：

- 很多接口不允许浏览器直连（CORS），此时要换成支持跨域的代理地址。
- 调用失败会自动回退离线库，并把失败原因写进建议正文，不会白屏。
- 设置页有「测试连接」，点一下就知道配通了没有。

## 六、V1 的能力边界（请按这个预期使用）

- **转写用浏览器自带语音识别**（Web Speech API）：只能用来"定位到大概哪句话"，不能当评分依据；Chrome 的识别需要联网，且中文用户环境偶尔不稳定。没有拿到转写时，仍可拖动波形打标并手写原句。
- **时间戳是句级，不是词级**：打标后取的是当前点附近的那一句（±4 秒窗口），不是逐词对齐。词级对齐需要服务端 ASR（faster-whisper 之类），属 V2。
- **素材朗读是系统 TTS**，不是真人录音；口音通过 `lang` 近似，音色取决于操作系统装了哪些语音包。
- **内置 20 条素材为原创示例文本**，不含任何第三方版权音频；用户上传与真人语料在 V2。
- **没有账号与云同步**：换设备、换浏览器 = 从零开始。
- 桌面优先，手机端可打开但布局未针对小屏录音场景优化。
- 隐私模式 / 无痕窗口下，关闭即清空。

## 七、相对最初方案的一处偏离

最初设想是 Next.js + Supabase + 服务端 faster-whisper。实际 V1 改成了 **Vite + React + TypeScript 纯前端**，原因：

1. V1 要验证的是**交互闭环是否成立**（打标 → 建议 → 只重录那几秒），不是基础设施；
2. 当前没有可用的 ASR / LLM 服务端密钥，纯前端可以先跑起来；
3. 单机形态与"各自为战、数据私有"的产品判断一致。

代价是上面第六节列出的那些：转写与时间戳精度不够、没有多设备同步。这些正是 V2 要补的。
